# OtvetWare

[![CI](https://github.com/Donut1133/OtvetWare/actions/workflows/ci.yml/badge.svg)](https://github.com/Donut1133/OtvetWare/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-informational)](LICENSE)
[![Rust](https://img.shields.io/badge/rust-1.85%2B-orange)](https://www.rust-lang.org/)

Настольный бот для **otvet.mail.ru**: карма, ответы, вопросы, комментарии,
подписки и жалобы — по многим аккаунтам сразу, из одного нативного окна.

Работает чистым HTTP: браузер нужен один раз, чтобы войти в аккаунт. Ни
Node.js, ни веб-панели, ни локального сервера — только один `.exe`.

---

## Что умеет

| Режим | Что делает |
|---|---|
| **Голоса** | Плюсы и минусы на все посты профиля или на конкретный пост/ответ |
| **Ответы** | Отвечает на свежие вопросы из ленты, по списку ссылок или по диапазону номеров — нейросетью, готовыми фразами или «коверканьем» |
| **Комменты** | Отвечает тем, кто написал под твоим ответом: читает уведомления и видит всю переписку в ветке |
| **Вопросы** | Публикует свои вопросы — от нейросети или из готового списка |
| **Подписки** | Подписка и отписка по списку профилей |
| **Жалобы** | Жалобы на профиль, на все его посты, на все ответы или на один конкретный пост |

Плюс разовые проверки, которые ничего не меняют: **кто голосовал** под постом
(с никами и знаком голоса) и **кто уже подписан** — матрицей «аккаунт → профили».

Поверх любого режима:

* **много аккаунтов** — по очереди или параллельно; в режимах с лентой ещё и
  общий лимит на аккаунт с покруговым, а в режимах по ссылкам лимит — сам список.
  Настройки прогона свои у каждого режима: «голоса всеми сразу» и «ответы по
  одному» — разные привычки;
* **прокси на аккаунт** (HTTP и SOCKS5, в том числе с логином) и автоматическая
  смена прокси после сбоев;
* **круги** — пройти по всем аккаунтам, подождать и начать заново, пока не нажмёшь «Стоп»;
* **ответы авансом** — номера вопросов у mail.ru идут подряд, и сайт принимает
  ответ на ещё не заданный вопрос: задаёшь диапазон номеров, и бот кладёт в него
  заготовки. Нейросеть здесь не при делах — вопроса ещё нет. Очередь номеров
  общая на прогон: сколько аккаунтов работает, во столько раз быстрее
  разбирается диапазон, и под каждым номером оказывается ровно один ответ;
* **нейросеть видит картинки** — половина вопросов на сайте это фото с подписью
  «как вам?», а в комментах отвечают мемом: текста у такого поста нет вовсе. Бот
  скачивает вложения вопроса и реплики собеседника и кладёт их в запрос рядом с
  текстом (нужна модель, которая умеет смотреть);
* **слова-приметы** — список слов, и бот берёт из ленты только те вопросы, где
  они встретились: сидит и ловит вопросы про VPN, а остальные даже не читает.
  Текст ответа при этом обычный, от нейросети;
* **пауза** — прогон замирает на месте и продолжается с той же точки: очередь
  аккаунтов, лимиты и счётчик сохраняются;
* **журналы** — бот помнит, на что уже отвечал, и не отвечает второй раз;
* **проверка отправки** — сайт отвечает «принято» и на то, что через секунду
  снесёт автомодерация. Бот перечитывает вопрос и, если ответа там нет, не
  засчитывает его и пробует другим текстом;
* **уникализация текста** — мелкие правки, как у живого человека: точка в конце
  то есть, то нет, «ещё/еще», словечко в начале. Без «#293508» в конце: именно
  за такой хвост и цеплялась автомодерация;
* **свои списки** готовых фраз, вопросов и реплик — прямо в панели режима;
* **пул картинок** — свои файлы заливаются на сайт один раз и дальше цепляются
  к постам без перезаливки;
* **отпечатки** — у каждого аккаунта постоянное «железо»: UA, client hints, язык,
  таймзона, экран, число ядер, память, GPU и шум canvas. Одна персона и на
  API-запросы, и на окно браузера: тридцать входов с одной машины выглядят как
  тридцать разных машин, а не как один человек с тридцатью аккаунтами.

С аккаунтом можно работать и руками: **открыть сайт в браузере под ним** (те же
куки, отпечаток и прокси), сменить ник, имя и аватар, войти заново, скопировать
куки.

## Быстрый старт

**Готовая сборка.** Скачай `otvetware-windows-x64.zip` со страницы
[Releases](../../releases), распакуй, запусти `otvetware.exe`. Внутри всё
нужное, включая браузер для входа в аккаунты: доустанавливать не надо ничего.

**Из исходников** (нужен [Rust](https://rustup.rs/) 1.85+ и, для входа в
аккаунты, браузер — его качает `patchright`):

```bash
git clone https://github.com/Donut1133/OtvetWare.git
cd OtvetWare
PLAYWRIGHT_BROWSERS_PATH=./browsers npx patchright@1.60.2 install chromium
cargo run --release -p otvet-gui
```

Системный Chrome бот не берёт намеренно: он обновляется сам, и его версия
разъезжается с той, которой представляется персона, а следов автоматизации он не
прячет. Браузер ищется только в `browsers/` рядом с программой (или по пути из
`OTVET_BROWSER`).

Дальше:

1. **Добавить аккаунт** → откроется браузер, заходишь в почту как обычно.
   Окно закроется само, аккаунт появится в списке.
2. Отметь аккаунты галочками, выбери режим, вставь ссылки.
3. **Запустить**. Пока чего-то не хватает, кнопка подсвечивает, чего именно.

Для режимов с нейросетью нужен ключ любого OpenAI-совместимого API
— по умолчанию это [DeepSeek](https://platform.deepseek.com), но адрес и модель
меняются в тонкой настройке. Ключ вводится прямо в панели режима.

## Как устроено

Два крейта: `otvet-core` — вся логика бота, `otvet-gui` — окно на
[egui](https://github.com/emilk/egui). Ядро ничего не знает про интерфейс, поэтому
его легко гонять тестами и звать из своих скриптов.

```
core/src/
  http.rs        HTTP-ядро: заголовки Chrome, куки, прокси, ретраи, антибот 418/429
  persona.rs     отпечатки: UA, client hints, экран, GPU — детерминированно по имени
  accounts.rs    accounts.json: модель и атомарная запись
  api.rs         кто я, жив ли аккаунт, карма, профиль, аватар
  votes.rs       голоса по профилю и по ссылке
  answerer.rs    режим «Ответы»: лента, пачки, единый чат с памятью, картинки
  replier.rs     режим «Комменты»: уведомления, цепочки, ответ в ветку
  asker.rs       режим «Вопросы»
  subscribe.rs   подписки
  complain.rs    жалобы
  runner.rs      параллельность, круги, лимиты, «Стоп»
  cdp.rs         вход через браузер и съём кук
  store_io.rs    атомарная запись файлов состояния
  uniq.rs        уникализация текста вместо «#случайных цифр»
gui/src/
  app.rs         раскладка окна, запуск и остановка
  accounts.rs    таблица аккаунтов и диалоги
  forms*.rs      настройки режимов
  console.rs     консоль прогона (виртуализованная — держит десятки тысяч строк)
  icons.rs       значки, нарисованные кистью: эмодзи в сером окне неуместны
  pool.rs        окно пула картинок
  theme.rs       серая тема и шрифты
```

Несколько решений, которые стоит знать, если будешь править код:

* **Голос ставится один раз.** Курсор пагинации у mail.ru инклюзивный: последний
  пост страницы приходит первым на следующей. Повторный голос сайт трактует как
  отмену, поэтому пройденные id запоминаются, а дубликаты ссылок схлопываются.
* **418 и 429 — это антибот**, а не ошибка сети: аккаунт на этом круге
  останавливается. Сетевые сбои, наоборот, статус аккаунта не меняют.
* **Место под лимитом занимается ДО отправки**, а не считается после. Когда
  пачка ответов уходит разом, проверка счётчика в начале круга не значит
  ничего: соседние задачи уже готовы постить.
* **Красным помечается только точный разлогин** (401/403). Мёртвый прокси не
  должен красить живые аккаунты.
* **Set-Cookie мержится обратно в аккаунт**: сайт продлевает сессию, и без этого
  бот со временем ходил бы с протухшими куками. В памяти — сразу, на диск —
  раз в пару секунд: полная перезапись `accounts.json` на каждый ответ сервера
  упирала параллельный прогон в диск.
* **«Стоп» рвёт запрос**, а не ждёт его таймаута.
* **Прокси с логином браузеру не показываем.** Chromium не умеет SOCKS с
  паролем и спрашивает пароль окном на HTTP-прокси, поэтому для любого прокси с
  логином поднимается локальный мост: браузер ходит на 127.0.0.1 без
  авторизации, а логин подставляет мост.
* **Пока работает один аккаунт, проверяется следующий.** Авторизация и карма —
  три запроса; делать их на старте, пока человек смотрит в пустой лог, незачем.
* **Пауза — это не «Стоп».** На паузе прогон замирает целиком: очередь
  аккаунтов, лимиты и счётчик остаются на месте, а на сайт не уходит ни одного
  запроса — проверка стоит в самом сетевом слое, а не только в паузах между
  шагами, поэтому «на паузе» значит именно это.
* **Бан отличается от разлогина.** Заблокированный аккаунт сайт отдаёт как
  живой: 200, профиль на месте, куки рабочие, — и только `user_status: -1`
  выдаёт правду. Поле приходит в том же ответе, что и проверка авторизации,
  поэтому распознаётся без единого лишнего запроса; такие аккаунты помечаются
  «бан» и в прогон не берутся.
* **Отказ по тексту — повод сочинить другой.** Если сайт вернул 4xx (не
  антибот), значит ответа, вопроса или реплики не создалось, и тот же текст он
  не примет. Бот перегенерирует и отправляет ещё раз — один раз на цель, чтобы
  при дневном лимите не жечь деньги на нейросети. Сетевой сбой и 5xx так не
  повторяются: там неизвестно, дошло или нет.
* **Опубликованное проверяется на месте.** Ответы, комменты и вопросы бот
  перечитывает с сайта через несколько секунд: «принято» в ответе API и
  «пережило автомодерацию» — разные вещи. У вопросов снос признаётся только по
  прямому «нет такого вопроса»: ошибиться в другую сторону — значит задать
  второй такой же.
* **Ответ считается отправленным только после проверки.** Если ответов под
  вопросом целая страница, «не нашли свой» значит «не поместился», а не
  «снесли»: второй ответ от того же аккаунта хуже, чем несосчитанный первый.

## Данные

Всё состояние лежит в папке данных — по умолчанию это `accounts` рядом
с .exe (подробности — в [data/README.md](data/README.md)):

`accounts.json` · `personas.json` · `styles.json` · `gif-pool.json` ·
`answered_*.ndjson` · `asked_*.ndjson` · `replied_*.ndjson` · `convo.json`

> **`accounts.json` — это живые сессии.** У кого файл, у того и аккаунты.
> Он и все журналы закрыты в `.gitignore`; не выкладывай их в публичный
> репозиторий и не прикладывай к issue.

Формат общий со старой Node-версией бота: обе могут работать на одной папке.

Папка самособирающаяся: если данные лежат прямо рядом с .exe (так выглядит
папка, скопированная от старой версии), программа при запуске сложит их
в `accounts` — и аккаунты, и отпечатки, и журналы, и профили браузера.
Переносим, а не копируем: две живые копии `accounts.json` — это разъезжающиеся
куки и разлогин на ровном месте. Запуск из клона проекта ничего не двигает:
там данные находятся выше по дереву и делятся с JS-версией.

## Честные ограничения

* **TLS-отпечаток (JA3)** — стека ОС, а не Chrome. Порядок заголовков, client
  hints и HTTP/2 воспроизведены, но полное совпадение даёт только запрос из
  настоящего браузера.
* **Вход через браузер** надевает персону целиком — UA с client hints, таймзону,
  язык, экран, ядра, память, строки WebGL и шум canvas (проверено сравнением с
  настоящей машиной). Чего он не закрывает — **список шрифтов**: он снимается
  измерением ширины текста, и подмена из JS ломает реальные метрики заметнее,
  чем сам факт одинаковых шрифтов. Лечится только разными хостами.
* **Капчу и SMS никто не решает** — вход всегда руками.
* Из старой Node-версии пока не перенесены: режим «текст → картинка», смена
  имени и аватара аккаунта, массовый импорт аккаунтов и сборщик гифок. Картинки
  из пула и из папки работают, остальное — в планах.

## Разработка

```bash
cargo test --workspace       # 136 тестов: юнит + интеграционные
cargo clippy --all-targets   # чисто, без предупреждений
cargo fmt --all              # форматирование
```

Интеграционные тесты поднимают **локальный сервер-заглушку** и гоняют по нему
настоящие циклы бота (`OTVET_BASE` переопределяет адрес сайта): голоса не
дублируются, антибот останавливает аккаунт, куки ротируются, «Стоп» срабатывает
мгновенно, тела запросов соответствуют контрактам сайта. Тем же сервером
подменяется и нейросеть, так что режим с ИИ проверяется целиком — от промпта до
записи в журнал. Сеть при этом не нужна.

Проверить работу на живом аккаунте:

```bash
cargo run -p otvet-core --example check -- "Аккаунт 1"   # жив ли, карма, ник
cargo run -p otvet-core --example feed  -- "Аккаунт 1"   # читается ли лента
```

Папку данных примеры ищут сами: `OTVET_ROOT`, потом `accounts` рядом с
собранной программой, потом первая папка вверх от текущей с `accounts.json`.
Если аккаунты лежат где-то ещё — `OTVET_ROOT=путь` перед командой.

Полный живой прогон по всем режимам (РЕАЛЬНО постит — нужен флаг подтверждения):

```bash
OTVET_LIVE=yes cargo run -p otvet-core --example live -- ask "Аккаунт 1"
OTVET_LIVE=yes cargo run -p otvet-core --example live -- answer "Аккаунт 2" <url>
OTVET_LIVE=yes cargo run -p otvet-core --example live -- vote-profile "Аккаунт 2" <профиль> 2
OTVET_LIVE=yes cargo run -p otvet-core --example live -- comments "Аккаунт 2"
```

Так и нашлись ошибки, которые не видит ни один офлайн-тест: сайт разбирает тела
запросов строго по типам и молча отвергает всё остальное.

Отдельный тест `persona::tests::reproduces_personas_written_by_js` следит за
совместимостью отпечатков со старой версией: если он покраснел — аккаунт под
теми же куками сменил бы «железо», а это ровно тот скачок, на который смотрит
антифрод.

<summary>English summary</summary>

**OtvetWare** is a native desktop bot for otvet.mail.ru (a Russian Q&A site):
karma voting, AI-written answers, replies to comment threads, questions,
subscriptions and abuse reports across many accounts at once.

Pure Rust: `otvet-core` holds all the logic, `otvet-gui` is an
[egui](https://github.com/emilk/egui) window. Requests go over plain HTTP with
per-account cookies, proxies (HTTP/SOCKS5) and stable browser fingerprints; a
real browser is only used once, to log in and harvest cookies over CDP.

Build with `cargo run --release -p otvet-gui`. Tests (`cargo test --workspace`)
run the bot's real loops against a local mock server, so no network is needed.
